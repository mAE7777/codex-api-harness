# Boundaries

## Billing and accounting

The gateway permits only `api.openai.com` Responses inference and its exact-input-count endpoint. Hosted tool declarations, unknown fields, unapproved service tiers, server-side storage, external file URLs and media endpoints are rejected. Locally supplied image data for model input is permitted; media generation is disabled. Text-only use is not proof of free inference.

Free-only mode requires a current, complete eligibility record and expires closed. The installer does not manufacture that record. In particular, it does not assume exact counting is free or that local-tool reasoning qualifies for complimentary tokens. `--allow-api-charges` explicitly bypasses the free-eligibility claim, **not** the daily reservation guard. Account payment/recharge controls are separate and must be checked in the provider's account UI.

New installations have no assumed model or token allowance. A single owner policy defines the models, pool mapping, actual daily allowances, safety margin, warning, output cap, reasoning and fixed service tier. The guest catalog, request validator and shared clients derive from it. Standard is recommended; Fast/Flex/Ultrafast require reviewed per-model support and project permission. Auto and silent paid fallback are disabled. Only daily UTC resets are supported. An account monthly allowance cannot be relabeled as a daily free pool. See [CONFIGURATION.md](CONFIGURATION.md).

Pre-0.3 installations retain their original settings through a read-only adapter. The optional legacy-five preset uses A 237,500 and B 2,375,000 after the 5% margin on reference pools 250,000 / 2,500,000. These are not universal entitlements or live account discovery. Policy schema/capability checks do not prove account access. Owners must verify current pricing, limits and tier permissions.

Before each generation, the gateway counts the complete replayed input, instructions, and tool definitions. It then durably reserves that input plus the request's maximum output, bounded by the owner policy's output cap. The recommended cap is 16,384 tokens. Provider output usage includes reasoning tokens. A request that cannot fit is rejected before generation. Counting may already have occurred, and its financial treatment is not assumed. Requests without complete usage retain their reservation. They are never silently refunded, retried, or rerouted.

One gateway owns the ledger. A session lock prevents duplicate launch/maintenance races. SQLite transactions and a separate witness detect inconsistent state; they are not tamper-proof against the host owner, malicious host software, or a simultaneous rollback of both files. Do not delete/restore state to regain quota. A changing clock or inconsistent ledger can stop requests for investigation.

In personal mode, the owner supplies today's prior usage for every pool and confirms that other organization clients are stopped. In shared mode, all participating machines use one coordinator. It atomically reserves against the organization, project, and member limits. The harness cannot predict or prevent unmanaged organization traffic. Separate projects do not create independent organization pools. Do not run an independent personal gateway against an organization whose pool is coordinated elsewhere.

Shared allocations are daily defaults plus same-day adjustments. Transfers move only unused, unreserved capacity; duplicate approvals do not grant twice. Pending prior-day reservations continue to constrain admission. An explicit request ID binds to member and normalized content: replays are refused, not regenerated. Answers are not cached for replay. The pinned native CLI has no verified stable automatic operation ID; the shared relay generates one for each host-to-coordinator attempt, and neither hop automatically retries.

The coordinator keeps project-restricted OpenAI keys on the owner's Mac. Members receive separate revocable gateway credentials, never those keys. It validates membership again before dispatch and stops on lost connectivity; no offline quota grant or local fallback exists. The owner sees prompts and responses while relaying them. Its member-facing HTTP listener is loopback-only, and owner administration uses a private local socket. Remote access uses a separate restricted SSH service with public-key authentication and forwarding limited to the coordinator; no normal shell, file subsystem, or host SSH-agent access is granted. This does not eliminate vulnerabilities in the host OS or OpenSSH.

New UTC days establish new budgets automatically. In-flight/unknown prior-day reservations carry conservatively; terminal cross-day usage is not discarded. A notice at the configured threshold (recommended 90%) uses actual plus reserved tokens and is claimed at most once per group/day across restarts. A crash after claiming can prevent display. Notice delivery failure does not loosen admission. Noninteractive notices use stderr after the command; usage itself remains one English line per approved pool; legacy A/B keeps two lines.

Requests admitted in the last configured maximum request lifetime plus 15 seconds of a UTC day (615 seconds for the legacy 600-second deadline; 915 for a 900-second Flex policy) also conservatively charge their confirmed usage against the next day. This covers ambiguous provider attribution across the maximum request lifetime; it is intentional overlap, so the next day may start with some usage. New admissions pause for the first 15 seconds after midnight UTC. A successful exact-count response must carry a valid GMT HTTP Date within six seconds of the gateway clock before inference can proceed. A missing or mismatched clock reference stops inference; the preceding count may already have occurred. These checks use the existing response and make no additional provider requests. They cannot detect an incorrect provider clock or uncoordinated organization traffic.

Cancel/timeout closes connections where possible, but cannot prove the upstream stopped computing. Unsent permits are voided; potentially dispatched requests retain their reservation. Under-reserved actual usage creates a safety stop. Reconciliation requires explicit completed-request evidence and preserves history; it is not an account billing query or automatic refund.

Streaming terminal events are held until clean EOF confirms consistent, valid usage; ordinary output still streams. Conflicting terminal records retain the full reservation and stop further model requests. Stop the gateway or coordinator, inspect `codex-api reconcile` (shared owner: `codex-api team reconcile`), create a `--template REQUEST_ID`, fill verified completed usage and evidence in the private review file, then use `--apply FILE`. The conflict stop clears only after every uncertain OpenAI request has been reviewed. Replaying an identical receipt can finish an interrupted clear without counting twice. A confirmed value above its reservation retains the stronger safety stop for investigation. Do not delete stop files or accounting state to resume.

## Files and processes

The VM receives the selected project through a live direct mount. Changes, deletion and Git operations affect the original project. All allowed project contents and Git history may be read by the agent and sent as model input. `.gitignore`, `.dockerignore`, project instructions and hidden filenames are not security boundaries.

The host API key and ledger stay outside the mount. The guest receives only a random local gateway token. That token permits requests within this gateway's policy; it is not the upstream API key. It is visible to in-guest tools, so do not describe it as inaccessible to the agent. Host subscription state, skills, plugins, browser profiles, SSH agent and other projects are not imported.

Additional native masks deny common environment/credential paths. Host checks run before counting and again before dispatch. Four exact `.env` template names accept only reviewed placeholder-like values. Known public CA bundle names get a content check; standard venv interpreter aliases target the guest runtime. External/broken symlinks and hard-linked files fail preflight.

Owner-selected exact relative paths can add native deny rules. Their contents are skipped by host preflight rather than copied or synchronized. They still have the process/privilege limitations below; a protected path does not erase secrets already present in Git history or readable copies.

**Linux deny-glob matches are a per-tool-process-start snapshot, scanned to depth 16.** A running watcher, shell or server can read a matching file created later if its other permissions permit it. Starting a new tool process rescans; continuing the old process does not. Request-time checks cannot undo a secret already copied to a log, memory or another filename. There is no continuous secret-content filter or filtered live filesystem mount. [Official permissions documentation](https://learn.chatgpt.com/docs/permissions#deny-reads-with-exact-paths-or-globs).

Inside the VM, Docker provides a private Docker engine and privileged development facilities. Native tool masks are defense in depth for ordinary execution, not an independent security boundary against malicious code with in-VM privileges. **Keep actual secrets outside every shared project.** Docker's VM boundary and the absence of host mounts remain the host isolation boundary. [Docker isolation model](https://docs.docker.com/ai/sandboxes/security/isolation/).

## Network and local tools

Runtime permits the authenticated localhost gateway and HTTPS GET/HEAD to `registry.npmjs.org:443`, `pypi.org:443`, `files.pythonhosted.org:443`. Other direct destinations, including OpenAI and GitHub, remain blocked. Global allows could widen runtime access, so preparation and startup reject them rather than silently replacing global policies. Docker organization governance and broader existing configurations require separate review.

Allowed hosts are still network access: query strings and paths can carry data, and package code can execute lifecycle/build scripts. This is not universal exfiltration prevention. npm audit/fund/update prompts are off; TLS certificate validation remains on. Package dependencies needing other registries, GitHub or CDN binaries will fail. Initial trusted image builds use broader build-time downloads; build access is not the runtime allowlist.

Playwright is installed for local pages. Installation does not grant arbitrary web browsing or authenticated host-browser access. Hosted execution, paid search, remote MCP and media tools do not become available because a local package is installed. Unknown tools fail closed. Supported local function/custom-tool names and request formats are tied to the pinned CLI release.

Only the fixed managed quota-notice hooks execute. They discard hook input and return a UI-only message. Project/user/plugin hooks are skipped. The optional extension manager snapshots reviewed text skills or skill-only plugin bundles and pins every byte. Code needs separate acknowledgement. It rejects declared MCP, hooks, credential dependencies, links and unsupported binary files. Native discovery remains off; a protected catalog supplies managed skills to the model, and `extensions list` shows them. Native plugin installation and the native skills picker are not the managed catalog. Static checks cannot prove behavior safe or prevent arbitrary instructions from asking the agent to run already-allowed commands. No extension expands the host mounts, allowed models, upstream credentials, network destinations or budget authority. This harness does not solve prompt injection.

## Privacy, storage and removal

The gateway does not log prompts, queries, tool outputs or raw provider error bodies. The ledger stores request hashes, operation correlation identifiers and accounting metadata. Private CLI history normally lives inside the persistent sandbox. Before a managed rebuild, selected JSONL history and allowlisted preferences are captured into a bounded private host backup, then restored automatically. This excludes subscription state, API keys, auth/config policy, native databases, plugins and hooks. Failed capture stops removal; failed rebuild retains the backup. The backup can contain conversation secrets and is never publishable. Selected paths, account IDs, configuration hashes and diagnostics are also private state.

Provider request storage is disabled with `store=false`. This does not override provider retention, logging, training/data-sharing choices or legal policies. The harness never opts into account data sharing automatically.

`stop` is reversible. `reset` removes only the sandbox whose recorded ID and workspace still match. `retire` resets that sandbox and archives private state, including credentials and usage; it is not secure erasure. Project files remain. Shared builder cache, daemon, Docker login and global settings are left alone. Deleting the source checkout does not revoke keys or erase installed state.

The host owner, host malware, upstream provider, selected project and third-party dependencies remain in the trust model. No sandbox can protect secrets the owner explicitly pastes into a model prompt.
